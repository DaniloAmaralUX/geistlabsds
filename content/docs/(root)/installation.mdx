## Pré-requisitos

Um projeto com o shadcn configurado (`components.json` presente). Se ainda não tiver:

```bash
npx shadcn@latest init
```

## 1. Tema

O tema aplica as cores e o raio do LAB / DESIGN aos tokens do shadcn, em claro e escuro. Instale uma vez por projeto.

<InstallCommand name="lab-design-theme" />

## 2. Componentes

Cada componente é um item do registry. Instale só o que for usar.

<InstallCommand name="button" />

<Callout title="Sobrescreve o arquivo do shadcn">
  Button, Badge e Input usam os mesmos caminhos do shadcn
  (`components/ui/button.tsx` etc.). Ao instalar, o CLI pergunta se pode
  sobrescrever; responda sim ou passe `--overwrite`.
</Callout>

Os [blocos](/docs/blocos) seguem o mesmo caminho: cada um é um item do registry, com o comando na sua página, e traz os componentes de que depende.

## 3. Uso

```tsx
import { Button } from "@/components/ui/button";
import { Note } from "@/components/ui/note";

export function Exemplo() {
  return (
    <Note
      type="success"
      action={
        <Button size="sm" variant="secondary">
          Ver
        </Button>
      }
    >
      Publicado com sucesso.
    </Note>
  );
}
```

## Dependências

Os componentes usam `class-variance-authority`, `radix-ui` e `lucide-react`, que o CLI instala quando faltam. Não há dependência além das que um projeto shadcn já tem.

## Validação

A instalação de cada componente publicado é conferida num projeto consumidor limpo, com build. O estado aparece na coluna "Instalação" do [roteiro](/docs/fundamentos/roteiro).
